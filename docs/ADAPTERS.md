# Адаптеры рецептов

`RecipeAdapter` — Kotlin-интерфейс: уникальный `id`, `detect(environment)` и `call(operation, arguments, environment, codec)`.
`AdapterRegistry` хранит провайдеры, проверяет совместимость и направляет запрос только в явно выбранный адаптер. Внешний мод может зарегистрировать провайдер при init через `RecipeAdapters.register(provider)`.

Каждый форк получает отдельный ID, проверку признаков и руководство. Mod ID `gregtech` недостаточен для выбора. Встроенный `gregtech-impact` проверяет namespace Impact, специальные карты и форму API; неизвестный или несовместимый GT не активируется. Проверка совместимости не доказывает точный коммит JAR. `provenance` разделяет sourceProfileCommit и сведения установленного мода.

Общий MCP-контракт:

| Операция | Назначение |
| --- | --- |
| list_adapters | Доступность и причины отказа |
| list_recipe_maps | Карты конкретного адаптера |
| search_machine_recipes | Поиск с фильтрами и пагинацией |
| get_machine_recipe | Детали ранее найденного рецепта |
| get_recipe_authoring_guide | Скилл и API конкретного профиля |

Вызовы адаптера требуют `adapter`. Руководство можно читать без установленного мода: `runtimeAvailable` показывает доступность игровых данных. Новый провайдер реализует эти операции; неизвестные операции должны возвращать ошибку. Новые специализированные операции также нужно объявить в каталоге stdio-моста и ClientTools.

GT подключается через reflection после detection: обязательной GT зависимости нет. ForgeMCP не загружает отсутствующие классы GT из собственного bytecode. Native ItemStack/FluidStack преобразуются codec на клиентском потоке игры. Адаптеры не должны изменять коллекции, стеки и состояние игры.

Модель различает machine и assembly-line, сохраняет входы/выходы, жидкости, NBT, шансы, флаги, энергию, special items/value, исследования и альтернативы. Дополнительные public поля попадают в extensions; непрозрачные значения дают warnings и complete=false. Динамические findRecipe результаты не перечисляются.

ID состоит из adapter/map/хеша данных. Порядок списка рецептов не участвует в хеше; локализованные имена и provenance исключены. SNBT сравнивается как строка. Одинаковое экспортируемое содержимое получает одинаковый ID; это не уникальный адрес Java-объекта. Кэш ограничен 4096 обнаруженными рецептами; чтение проверяет наличие объекта и неизменность содержимого. После смены сессии или изменения коллекции нужен повторный поиск.

Скиллы лежат в ресурсах assets/forgeaimcp/mcp/skills и автоматически распаковываются в forgemcp/skills. Их также отдаёт get_recipe_authoring_guide, поэтому ИИ может прочитать инструкции без глобальной установки скилла. Упаковку нового скилла нужно добавить в McpInstallation. Генерации и применения Kotlin-кода через MCP нет: ИИ пишет код самостоятельно по руководству и runtime данным.
