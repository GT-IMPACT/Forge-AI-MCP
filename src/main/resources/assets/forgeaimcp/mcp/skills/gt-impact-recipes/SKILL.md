# Рецепты GT Impact

Пиши Kotlin-код самостоятельно под задачу пользователя. MCP возвращает данные и документацию; инструментов генерации или регистрации рецептов в игре нет.

Если GT Impact установлен, рецепты верстака и печки регистрируй через `GT_ModHandler`, даже если их данные/черновик используют adapter `minecraft`. Проверь `list_adapters.craftingRegistration` и раздел верстака/печки в [references/authoring.md](references/authoring.md). Источник данных и владелец регистрации различаются. Не обходи GT прямой регистрацией Forge и не переноси методы на неизвестный форк.

1. Вызови `list_adapters`. Для установленного мода используй `gregtech-impact` только при `available=true`. Один mod ID `gregtech` не определяет форк. Если профиль несовместим, выясни нужный форк вместо применения API Impact.
2. Прочитай `get_recipe_authoring_guide` с `adapter="gregtech-impact"` и [references/authoring.md](references/authoring.md). Руководство доступно и без установленного GT, но `runtimeAvailable=false` означает, что игровые данные этого профиля недоступны.
3. Найди карту через `list_recipe_maps`, предметы через `search_items`/`get_item`, жидкости через `search_fluids`, группы через `search_oredict`/`get_oredict`. Используй реальные ID, metadata и NBT, не угадывай номера метапредметов и названия жидкостей.
4. Исследуй похожие рецепты через `search_machine_recipes`; точные данные возьми через `get_machine_recipe`. Укажи карту и направление поиска. Проверяй `complete`, `warnings`, `kind` и `provenance`. Обычные результаты NEI — отображение, а не полная модель машинного рецепта.
5. Различай машинные рецепты, Assembly Line с исследованиями и альтернативами, визуальные/fake карты и топливо. Выбирай точку регистрации по смыслу задачи, а не только по похожему имени карты.
6. Напиши или измени Kotlin-код в целевом моде, следуя его структуре загрузки. Проверь сборку доступного проекта. Проверку сборки и наличие рецепта в запущенной игре сообщай отдельно: одно не доказывает другое.

Если пользователь заполнил визуальный редактор, найди черновик через `list_recipe_drafts` и прочитай `get_recipe_draft` с его `id`. Черновик описывает желаемый рецепт, а не существующий зарегистрированный рецепт. Сохрани заданные слоты, альтернативы, oreDictionary, NBT, research и notes; сверяй ID и карту с текущей сборкой. Поля source/sourceSpecial служат исходными данными импортированного рецепта; непрозрачные значения требуют понимания API, не пропускай их молча. Не считай черновик корректным только потому, что его удалось сохранить.

Сохраняй количество, NBT, вероятности, нулевые количества входов, жидкости, длительность, EU/t, исследования и special value. Зарегистрированные стеки уже могли пройти нормализацию; по ним нельзя восстановить исходный OrePrefix/Materials, исходный код или рецепт до оптимизации. Не объявляй данные полными при непрозрачных полях или динамических рецептах. Подключай новый форк отдельным adapter ID и отдельным скиллом.
